# WASM SLMP 書込みの制御試験

この試験はテスト機 R `192.168.11.200:3109` の `D3010/u16` 単点だけを対象とする。実機ケースは `#[ignore]` と明示 opt-in で保護し、通常起動の WASM 登録や本番鍵・設定は変更しない。

- guest: `tyaro/banto-driver-wasm` の `fdb161520019b81a22bc2fec2bc9bf3d837f5bd3`
- 検証済み component SHA-256: `3cb4451f712fc4c0de3ab83e85f9bb8aefde6fa26b5de5a8b09971748c9d714e`
- 直接試験では実 transport の宛先と送信前のフレームを限定する。Hub API 試験では一時 DB に登録する接続・タグの入力を登録前に検査し、保存後の接続先を broker 起動前に再確認する。Hub の60秒窓の書込みレート制限は全体・タグ単位とも2回に設定する。
- Hub API 試験の一時キーはこのタグの read/write scope のみ、有効期限10分。外部 listener は立てず、成功時には revoke する。

どちらも試験値の書込み1回と原値の復元1回で終了した。Hub 経路では `read-now` と単票書込み API を使用し、write_control の無効時拒否、write scope、broker 直列経路、成功監査2件、write_control の再無効化、キー revoke、一時 DB の削除を確認した。終了後に対象への Established 接続は残っていなかった。API キー平文はログに記録していない。

直接経路の `WireGate` は送信フレームを検査し、累積で最大2回の書込みを許す。Hub 経路の2回制限は60秒のスライディングウィンドウによるレート制限であり、同じ累積 `WireGate` は持たない。今回の手順は各経路で試験値と復元値を各1回書き込んだため、両経路を合わせて4回の書込みである。

一時キーは正常終了時に revoke を確認した。異常終了時の revoke は保証されず、一時 DB の後始末とキーの10分期限に依存する。revoke 後のアクセス拒否は検証していない。

これらはテスト専用アプリと固定 guest の確認であり、通常起動の登録、本番の鍵配布、管理画面、他の PLC・番地・型、結果不明時の回復操作は検証していない。結果不明時は再送・自動復元せず停止する。
