## 0. 位置づけ

banto-hub の MCP サーバー（`POST /mcp`、自前の最小 JSON-RPC、既存 API キー認証）を、
実機 三菱 R08ENCPU（SLMP/TCP）に対して MCP エンドポイントだけで駆動し、読み書きが
実運用の経路（`crate::write_path::execute_write`）どおり動くことを確認した記録。
方針により**実機 IP は本書に記載しない**（機種名・ポート・実測事実のみ。docs/ の IP 非記載方針）。

## 1. 構成（複数接続・複数グループ・全データ型）

| 接続    | ポート | 収集グループ(周期) | タグ(アドレス/型)                                                                   |
| ------- | ------ | ------------------ | ----------------------------------------------------------------------------------- |
| plc3201 | 3201   | g_fast(500ms)      | i16a(D3000/i16), u16a(D3001/u16), i32a(D3002/i32), u32a(D3004/u32), f32a(D3006/f32) |
| plc3201 | 3201   | g_slow(2000ms)     | bit0(M1000/bit), i16slow(D3020/i16)                                                 |
| plc3200 | 3200   | g1(1000ms)         | i16b(D3100/i16), u16b(D3101/u16)                                                    |
| plc3101 | 3101   | g_3101(1000ms)     | i16c(D3200/i16)                                                                     |

**3接続を同時セッションで接続成功**（ポート 3101 / 3200 / 3201、1ポート1セッション並行）。
開放ポートは 3101〜3110・3200・3201（3100 はタッチパネル占有）。

## 2. MCP ツール

`initialize` / `tools/list` → 4ツール（`list_tags` / `read_tag_values` / `get_server_status` /
`write_tag_value`）。`list_tags` は全接続横断で10タグを列挙（read スコープの per-tag フィルタ動作）。

| ---------------------- | --- | ---------- | ------------ | --------------- |
| plc3201.g_fast.i16a    | i16 | -100       | -100.0       | OK（負値）      |
| plc3201.g_fast.u16a    | u16 | 50000      | 50000.0      | OK（>32767）    |
| plc3201.g_fast.i32a    | i32 | 100000     | 100000.0     | OK（2ワード）   |
| plc3201.g_fast.u32a    | u32 | 3000000000 | 3000000000.0 | OK（>i32max）   |
| plc3201.g_fast.f32a    | f32 | 3.14159    | 3.141590118… | OK（float精度） |
| plc3201.g_slow.bit0    | bit | true→false | 1.0→0.0      | OK（bool）      |
| plc3201.g_slow.i16slow | i16 | 4242       | 4242.0       | OK              |

## 4. ゲート（安全機構）が MCP でも作動

- **書き込み受付 OFF**: MCP 書き込みが `writes_disabled` で拒否 → ON にして通過。
- **値の範囲外**: i16 に 40000 を書くと `value_out_of_range`（範囲 [-32768, 32767]）で拒否され、
  値は -100 のまま（書かれていない）。
- **スコープ不足/未知タグ**: `write:{tag}` スコープの無いタグは `missing_write_scope`
  （スコープ検査が catalog 解決より先）。
- いずれも REST と同じ `execute_write` 経由で、MCP 専用の抜け道は無い（§3.7）。

## 5. 運用上の重要な発見

- **収集開始（新しい run）は書き込み受付を False にリセットする**（安全設計）。書き込みは
  収集開始の**後**に `POST /api/write-control/enable` が必要。開始前に有効化しても効かない。
- 書き込みは即時に実機へ届くが、読み戻し値は収集の次ポーリングで反映されるため、
  slow(2s) グループは数秒待って確認する。
- 実機の D/M は保持メモリのため、検証開始時に既存値が残っていた（例: D3002-3 に 0x12345678、M1000=1）。
