# 筋書きで動く模擬 PLC（banto-plc-sim）の設計

状態: 実装済み（2026-11-26、#1335 の PR2）。

## 目的

設備（PLC）ができる前に、本物のサーバー（Hub・ChronoGazer・派生アプリ）を TCP で模擬の PLC につなぎ、サービス化・キオスク表示・遠隔表示を含めた結合を確かめる。`apps/chronogazer/core/examples/dev_plc.rs`（`banto_plc::ramp`）は値の動きが固定なので、装置らしい場面（運転と停止の繰り返し、異常の発生、通信の途切れ）を再現できない。

アプリのコードを書かずに、**設定ファイル（割付と筋書き）だけ**で模擬の PLC を立てる。同じ筋書きと時刻からは、いつ起動しても同じデバイスの値になる。

## 置き場所と依存

- crate `crates/banto-plc-sim`（内部 crate、`publish = false`）、実行ファイル `banto-plc-sim`。
- 依存: `banto-plc`（feature `simulator`。SLMP・Modbus の `Simulator::start_on`・`set_*`・`hang`）、`banto-scenario`（筋書きの形 版 1、[banto-scenario-format.md](banto-scenario-format.md)）、`banto-driver-api`（`DataType`・`WordOrder`）、`serde`・`serde_json`、`tokio`。
- 引数は手で読む（`dev_plc` と同じ。clap は足さない）。

## 起動

```text
banto-plc-sim <設定ファイル> [--listen <addr:port>] [--at <UNIX 秒>] [--freeze]
```

| 引数         | 意味                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 設定ファイル | 下の JSON。筋書きの相対パスは設定ファイルの置き場からたどる                                                                      |
| `--listen`   | 設定の `listen` を上書きする                                                                                                     |
| `--freeze`   | 筋書きの `freezeAtSec` の時刻で止める（無ければ起動の誤り）                                                                      |
| `--at`       | その時刻で止める（`--freeze` より優先）。止めた時刻でも出来事・`hang` は同じ規則で決まる（止めた時刻が `hang` の中なら答えない） |

待ち受けの既定は `127.0.0.1`。LAN に出すときは `--listen 0.0.0.0:…` を明示する（模擬の PLC を不用意に晒さない、`dev_plc` と同じ）。止めるのは Ctrl+C。

## 設定ファイル

```json
{
	"format": "banto-plc-sim",
	"version": 1,
	"protocol": "slmp",
	"listen": "127.0.0.1:15000",
	"scenario": "plant.scenario.json",
	"periodMs": 100,
	"wordOrder": "low_high",
	"map": [
		{ "signal": "Tank.Level", "address": "D100", "type": "i16", "scale": 10 },
		{ "signal": "Inflow", "address": "D102", "type": "f32" },
		{ "signal": "Hours", "address": "D110", "type": "u32", "wordOrder": "high_low" },
		{ "signal": "Pump.Run", "address": "M10" },
		{ "signal": "Lamp", "address": "D120.3" }
	],
	"faults": [{ "kind": "hang", "atSec": 100, "durationSec": 15 }]
}
```

| 項目                | 意味                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `format`・`version` | `"banto-plc-sim"` と `1`。ほかは読まない                                                                                                                                                    |
| `protocol`          | `"slmp"` か `"modbus"`                                                                                                                                                                      |
| `listen`            | 省略時 SLMP `127.0.0.1:15000`、Modbus `127.0.0.1:15020`（`dev_plc` と同じ）                                                                                                                 |
| `scenario`          | 筋書きのファイル（形 版 1）。設定ファイルからの相対パス                                                                                                                                     |
| `periodMs`          | 値を置き直す周期（既定 100、10〜60000）                                                                                                                                                     |
| `wordOrder`         | 2・4 ワードの型の既定の並び（`high_low`・`low_high`、既定は Hub の接続と同じで SLMP が `low_high`、Modbus が `high_low`＝`banto-tags` の `default_word_order_for`）。割付ごとに上書きできる |
| `map`               | 信号 → 番地の割付。番地の書き方は Hub のタグと同じ（SLMP は `D100`・`M10`・`D120.3`（16 進のビット）、Modbus は `40001`・`00001`・`40001.3`）                                               |
| `faults`            | 通信の途切れ。筋書きの周期の中の秒で書く（出来事と同じ規則: `atSec` は 0 以上・周期未満、`durationSec` は `periodMs` 以上・周期以下、周期の終わりをまたいでよい）                           |

`map` の 1 項目:

| 項目        | 意味                                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `signal`    | 筋書きの信号の名前（無ければ読込の誤り）                                                                                                                          |
| `address`   | 番地。`protocol` と合わない書き方は読込の誤り                                                                                                                     |
| `type`      | `DataType` の綴り（`bit`・`i16`・`u16`・`i32`・`u32`・`f32`・`i64`・`u64`・`f64`）。ビットの番地（`M10`・`00001`・`.N` つき）は省略時 `bit`、ワードは省略時 `i16` |
| `scale`     | 置く値 = 筋書きの値 × `scale`（既定 1、有限で 0 でない）。整数の型は 0 から遠い方へ丸め、型の範囲で飽和させる（飽和は信号ごとに最初の 1 回だけ警告）              |
| `wordOrder` | この割付だけの並び                                                                                                                                                |

- ビットの信号はビットの番地（とワードの中のビット）にだけ、数値の信号はワードの番地にだけ割り付ける（違えば読込の誤り）。ビットの割付に `scale`・`wordOrder` を書いたら読込の誤り（効かない項目を黙って受けない）。
- 同じ番地（ワードの幅を含めて重なる）に 2 つ割り付けたら読込の誤り。ただし同じワードの別のビット（`D120.3` と `D120.4`）は重なりと見なさない。
- Modbus の `3xxxx`（input register）・`1xxxx`（discrete input）にも置ける（読み出しの専用の領域）。
- 知らない項目・`null` は読込の誤り（筋書きの形と同じ厳しさ）。

### 通信の途切れ（`faults`）

`hang` の間は、要求を受けても答えない（`Simulator::hang`）。接続は切らない（客側の応答の時間切れを再現する）。間が終わると、新しく受けた要求に答えるのを再開する（`stop_hanging`）。途切れの間に要求を受けた接続は、その要求で止まったままで、間が終わっても答えない。客が時間切れで接続を張り直す前提（Hub のドライバは時間切れで接続を閉じる）。途切れの間も値は置き直し続けるので、戻ったときの値は時刻どおり。途切れの中か外かは、値を置き直す周期（`periodMs`）の刻みごとに、その刻みの時刻で決める。始まり・終わりは設定の時刻から最大 1 周期遅れる（周期の刻みでの近似を仕様とする。2026-11-26 オーナーのレビュー #1351 の P3）。刻みの間に収まる短い途切れを抜かさないよう、`durationSec` は `periodMs` 以上を要る（短ければ読込の誤り）。**通信の途切れを筋書きの形に入れず、ここに書く**のは 2026-11-26 オーナー決定（筋書きの形 版 1 をブラウザの模擬と共有したままにする）。

## 値の置き方

- **最初の値を置いてから要求を受け付ける**（2026-11-26 オーナーのレビュー #1351 の P2）。待ち受けを始めた後、最初の要求に答える前に、起動の時刻で全信号を置き終える。`--freeze` で立てた直後の最初の読みも止めた時刻の値になる（模擬 PLC を立て直したとき、張り直しを繰り返す客が未設定の 0 を読まない）。
- その後は `periodMs` ごとに、今の時刻 t（`--at`・`--freeze` なら止めた時刻）で全信号を評価し、割付の番地へ置く。
- 外から書き込まれた番地は、シミュレータの held の規則で以後置き直さない（`banto-plc` の各シミュレータの「held set」。SCADA が書いた設定値はそのまま残る）。
- 置く順は割付の並びのまま。1 周期の中の値はすべて同じ t で決める。

## 試験

- 設定の読込: 正しい例・誤りの例（知らない項目・番地の書き方の違い・重なり・型の不一致・無い信号・`faults` の範囲）。
- 値の符号化: 型ごと・並びごと・`scale`・丸め・飽和。
- 結合: 実の TCP でシミュレータを立て、生の要求のフレームで読み（`banto-plc` にはもうクライアントが無い）、止めた時刻の値が筋書きの評価と一致する（SLMP・Modbus）。`hang` の間は時間切れになり、間の後は張り直した接続で読める。起動の口を通して立てた直後の最初の読みが、止めた時刻の値になる（明示の `tick` を挟まない）。途切れの境界（始まりの直前・直後、終わりの直前・直後の刻み）と、`durationSec` が `periodMs` より短い設定の誤り。

## やらないこと（版 1）

- 筋書きの形の変更（版 2）。式で別の信号を計算すること。
- 答えない以外の異常（終了コードの応答・壊れたフレーム）の筋書き化。シミュレータに口はあるので、要れば版を上げて `faults` の種類に足す。
- 複数のポート・複数の局を 1 つの実行ファイルで立てること（要るなら設定ファイルごとにプロセスを分ける）。
