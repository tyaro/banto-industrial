# #383 段階3 P6 実機確認（Hub 経由の SLMP と直結 SLMP の比較）

状態: **実施済み（2026-10-11）**。ハーネスの判定は本番実行・補助実行とも全段 PASS。合否の最終判断はレビューで行う。
最終更新: 2026-10-11（初版）

[plan.md](plan.md) §5 の #383 段階3 の手順 P6「実機確認（Hub 経由の SLMP と直結 SLMP を別ポートで比較）」の記録。
ChronoGazer の Hub 経由のタグの収集（P3〜P5: `apps/chronogazer/core/src/hub.rs`・`collect.rs`・
`crates/banto-collect/src/external.rs`）が、実 PLC を相手に直結 SLMP の収集と同じ値を記録することを確かめた。

## 1. 構成

| 項目        | 内容                                                                                                                                                                                               |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PLC         | 三菱 R08ENCPU（IP は記録しない。実行時に環境変数 `PLC_HOST` で渡す）                                                                                                                               |
| SLMP        | Hub → PLC は TCP **3101**、ChronoGazer の直結 → PLC は TCP **3102**（別ポート・1 ポート 1 接続）                                                                                                   |
| Hub         | このコミットの `banto-hub`（debug ビルド）を**ハーネスが子プロセスとして起動**。`127.0.0.1:8731`、一時 DB・データ。インストール済みの BantoHub サービスは使っていない                              |
| ChronoGazer | GUI を通さず、デスクトップと同じサービス層（`HubService`・`CollectorService`・`register_from_hub`）を同じプロセスで組み立てる。キーは `MemoryKeyStore`                                             |
| タグ        | 両側とも同じ 25 本: D3000〜D3009（i16）、D3010〜D3013（u16）、D3014・D3016・D3018（i32、2 ワード）、M1000〜M1007（bit）。周期は両側とも 1000 ms。**読み取りのみ**（書き込みの API は一切呼ばない） |
| ハーネス    | `apps/chronogazer/core/examples/hub_p6_compare.rs`（製品コードは変更していない）                                                                                                                   |

### Hub の構成方法（管理者アカウントは作っていない）

素の banto-hub は試運転モード（未ロックダウン）で起動するので、構成（PLC 接続・収集グループ・タグの作成と
`POST /api/collection/start`）は loopback の `POST /api/auth/grant/commissioning`（資格情報なしの合成 admin の
grant、`apps/banto-hub/core/src/commissioning.rs`）の下で行った。ChronoGazer の API キーは `HubService::connect` が
試運転中の Hub に自己発行させた（デスクトップの「Hub 接続」と同じ経路）。発行したキーは最後に、記録
（`hub.record`）の接続先が一時 Hub であることを確かめてから、その `key_id` だけを grant の下で失効させた。

ChronoGazer 側の Hub 経由のタグは、P4 の「Hub から追加」と同じ `register_from_hub`（新しいグループ・周期
1000 ms、Hub 接続は暗黙に作成）で、Hub のカタログから登録した。

### 2.2 補助実行（定常 30 秒 + Hub の収集の stop / start）

`P6_OUTAGE=collection`（Hub のプロセスは生かしたまま `POST /api/collection/stop` → 15 秒後に `start`）。全段 PASS。

- 定常区間: 行数 直結 32 / Hub 経由 32、25 組とも null は先頭 1 行だけ・値は全一致。
- 停止から 846 ms で Hub 経由の全タグが Bad + null、直結は全タグ good のまま。記録は Hub 経由 14 行すべて null、
  直結 14 行すべて値あり。再開から 1.8 秒で good に戻った。
- **イベントは出ない**（Hub の接続キーに `plc_disconnected` / `plc_reconnected` が無い）。Hub の接続キーのイベントは
  **Hub とのリンク（購読）**の切断・再接続を表し（`crates/banto-collect/src/external.rs` のモジュール doc の
  `LinkTracker`）、Hub の収集を止めてもリンクは Live のままで値だけが Bad になるため。設計どおりの動作として、
  ハーネスはこの場合にイベントが出ないことを期待値にしている。

## 3. 分かったこと・限界

- **静止値での一致と、on-change 配信でも周期ごとに記録されること**: 試験中の PLC の値は変化しなかった
  （各タグ 1 種類の値）。Hub は値を変化時にだけ配信するが、Hub 経由のタグは直結と同じく毎周期 1 行ずつ記録され、
  行数は直結と一致した（P3 の「Live + good の定常値は周期ごとに記録して Good のまま」を実機で確認）。
- **変化する値の追従は確かめていない**: PLC へ書き込まない条件のため。ハーネスは変化がある場合に備えて、
  時刻が 1 周期以内の行同士を比べ、不一致は ±2 周期の直結の値のどれかと合えば時刻ずれとして扱う
  （どれとも合わない不一致を数える）。
- **開始直後の 1 行は両側とも null**: 最初の周期の行は、直結でも Hub 経由でも値が届く前に書かれる。Hub 経由に
  固有の欠落ではない。
- **Hub 側の PLC の停止（Hub は生きている）は ChronoGazer のイベントに出ない**（2.2）。値は Bad + null で記録
  されるので欠測は残るが、イベント一覧からは Hub のリンクの切断と区別して見えない。設計どおりだが、運用上
  それで足りるかは判断が要る。
- 製品の不具合は見つからなかった。

## 4. 再実行の手順

```text
cargo build -p banto-hub-core --bin banto-hub
cargo build --example hub_p6_compare -p chronogazer-core
PLC_HOST=<PLC の IP> P6_WORK_DIR=<一時ディレクトリ> P6_OUTAGE=process \
  target/debug/examples/hub_p6_compare.exe
```

環境変数（ポート・秒数・停止の方式）はハーネスのモジュール doc を参照。ハーネスが起動した Hub は終わりに止まる。
一時ディレクトリ（Hub と ChronoGazer の DB・データ・`hub.log`）は手で消す。
