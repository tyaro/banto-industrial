## 1. 安全

- **実 PLC の時計を書き換える**。iQ-R は変更のたびにイベント履歴に「時計設定」（イベントコード 24000）が残る。Q のイベント履歴に何が残るかは要確認。時計が飛ぶと PLC 側の時刻付きのログ・スケジュールに影響する。
- **試験用の PLC か、運用に影響しない時間帯で行う**。運用中のラインの PLC では行わない。
- **他の時計合わせを止める**: PLC 自身の SNTP の時刻設定、PLC のプログラムの時計の書込み（`DATEWR` や SM210 を使う回路）、GOT の時刻同期など。互いに上書きし、結果を読み違える。止められないなら、その PLC での試験を見送る。SNTP の無効化にはパラメータの書込みと CPU のリセットが要る見込み（要確認）。止めたものは記録表に書き、後片付けで戻す。
- **Hub の定期の時計合わせは試験中ずっと無効のまま**（`clockSync.enabled` は既定の偽。`PUT .../clock-sync` を呼ばない）。時計合わせは手動の `POST .../clock-sync`（画面の「今すぐ PLC の時計を合わせる」）だけで行う。手動の実行は Hub の `enabled` を問わない。
- **ゲストの `clock_set` は試験の間だけ `enabled`**。試験後に `disabled` へ戻す（§6）。
- **CPU を STOP にする操作（H-1）と、PLC のプログラム・パラメータの書込みはオーナーが GX Works3（iQ-R）・GX Works2（Q）で行う**。Hub からは STOP・RUN を操作しない。
- **GX Works で SD210 以降に値を入れて SM210 を ON にする操作（H-2・H-3）では、暦にない日付（2 月 30 日など）を使わない**。iQ-R のマニュアルでは、範囲内で暦にない日付はエラーにならずに書かれ、時計機能が正常に動かない。わざと断らせるときは月 13 のように範囲の外にする（13 月 32 日は SM211 が ON になり、書き込まれない）。
- 試験の前に、PLC のプロジェクト（プログラム・パラメータ）を GX Works で読み出して保存しておく。試験用の回路を足すなら、終わったら元に戻す。
- 一時 Hub は loopback にだけバインドし、インストール済みの Hub と root・profile を共有しない（§3.3）。

### 1.1 SM213 を ON・OFF する方法

H3 の読取りは SM213 が OFF なら `rejected` で、SD210 以降を読まない（ゲストの `clock_read.rs` の段 1）。SM213 は次のどちらかで切り替える。

- **案 A（推奨）: 試験用の回路**。M100（未使用の内部リレーを当日選ぶ。要確認）で SM213 を切り替える。M100 は GX Works のデバイステスト（現在値の変更）で ON・OFF する。

  ```text
  LD   M100
  OUT  SM213
  ```

- **案 B: デバイスの直接操作**。プログラムが SM213 を触らない場合だけ、GX Works のデバイステストで SM213 を直接 ON・OFF する。プログラムが SM213 を OUT していると、次のスキャンで戻される。

GX Works3・GX Works2 のデバイステストとモニタのメニューの位置は要確認（GX Works3 は［デバッグ］の現在値の変更、GX Works2 は［オンライン］→［デバッグ］→［デバイステスト］の見込み）。

### 1.2 時計の値を SM213 に頼らずに見る方法

H-5・H3-2 は、SD210 以降とは別の手段で「時計の本当の値」を見ないと判定できない。次を当日どれか 1 つ以上用意する。

- **案 A（推奨）: `DATERD` で時計を読む試験用の回路**。毎スキャン時計を D1000 以降に読む。Hub にも D1000–D1006 を u16 のタグ（読取り専用）として登録し、周期 1000 ms で記録する。

  ```text
  LD      SM400
  DATERD  D1000
  ```

  `DATERD` が SM213 に依らず時計を読むこと、格納の形（iQ-R・Q とも D1000 から年（4 桁）・月・日・時・分・秒・曜日の 7 ワード、BIN の見込み）、D1000–D1006 が空いていることは、当日の前にプログラミングマニュアルで確かめる（要確認）。STOP 中は回路が動かないので、H-1 では使えない。

- **案 B: イベント履歴の時刻**。iQ-R の「時計設定」（24000）の行の発生時刻を GX Works3 のイベント履歴で見る（メニューの位置と、時刻が変更の前か後かは要確認）。
- **案 C: GX Works の時計設定の画面**（［オンライン］→［時計設定］の見込み、要確認）。PLC の今の時計を表示するかは要確認。表示しないなら、時計をわざとずらす（§4.3）・戻す（§6）ためだけに使う。

### 3.3 Hub の起動

P6 と同じく、インストール済みのサービスを使わず、作業用のフォルダで一時 Hub を起動する。

1. インストール済みの Hub を見る。`sc query BantoHub`・`sc qc BantoHub` と、デスクトップシェル `banto-hub-shell.exe` が動いていないこと（implementation-checklist §2 の 12・13）。動いていれば止める・戻す手順を先に決める。
2. 画面を建て直してから embed-ui の exe を作る（§2 の 7。ビルドが一瞬で終わったら `apps/banto-hub/core/src/assets.rs` を `touch` して作り直す）。

   ```text
   pnpm --filter banto-hub build
   cargo build -p banto-hub-host --bin banto-hub --features embed-ui
   ```

   P-0a の結論が「試験用のビルドに一時鍵を入れる」なら、この exe だけに入れる（コミットしない）。

3. プラグインを置く: `<ProgramData>\BantoHub\plugins\<id>\<version>\` に `manifest.json`・`component.wasm`・`signature.ed25519` の 3 つだけ（他のファイルがあると断る）。
4. 環境変数を付けて起動する（P6 のハーネスと同じ名前。ポートは空いていることを先に確かめる）。

   | 環境変数                  | 値                                                                                                  |
   | ------------------------- | --------------------------------------------------------------------------------------------------- |
   | `PORT`                    | 空いているポート（例 8731）                                                                         |
   | `BANTO_BIND`              | `127.0.0.1`（試運転モードは loopback でしか起動しない）                                             |
   | `BANTO_DB`                | `<作業>\hub.sqlite3`                                                                                |
   | `BANTO_HUB_DATA`          | `<作業>\hub-data`                                                                                   |
   | `BANTO_HUB_ROOT`          | `<作業>\root`                                                                                       |
   | `BANTO_HUB_PROFILE`       | 試験ごとに一意（例 `clock-<日付>`）                                                                 |
   | `BANTO_WASM_PLUGIN`       | `<id>@<version>`（P-0b。t12 の manifest なら `slmp-wasm-operational-write@0.1.0`）                  |
   | `BANTO_WASM_WRITE_PLUGIN` | `BANTO_WASM_PLUGIN` と同じ文字列（運用書込みの loader。時計合わせはこの loader のゲストだけが出す） |

5. ログ（`hub.log`）に `WASM plugin registered: <id>@<version>` が出ることを確かめる。`WASM plugin rejected` なら理由を記録して止める。
6. 管理の操作は試運転モードの grant（`POST /api/auth/grant/commissioning`、loopback だけ）で得たトークンで行う。トークンは記録に書かない。応答の形は要確認（P6 のハーネスを参照）。

読取り専用の loader（`BANTO_WASM_WRITE_PLUGIN` なし）で読み込むと、時計合わせは `notOffered`（何も送らない）になり、読取りだけが出る。

### 3.4 接続・タグの作り方

時計合わせ・読取りは、適用済みのカタログにあって収集中（broker セッションが接続済み）の接続にだけ送る。無ければ送らずに `unavailable`。

1. 接続を iQ-R・Q で 1 つずつ作る（画面の接続の編集が楽。REST の本文の形は要確認）。protocol は §3.3 の id。設定は次のとおり。

   | キー               | iQ-R                     | Q                                                          |
   | ------------------ | ------------------------ | ---------------------------------------------------------- |
   | `host`・`port`     | PLC の IP・SLMP のポート | 同                                                         |
   | `transport`        | `tcp`（既定）            | `tcp`（既定）                                              |
   | `frame`            | `4e`（既定）             | PLC の Ethernet の設定に合わせる（要確認）                 |
   | `network_no`       | `0`（既定。自局だけ）    | `0`                                                        |
   | `target_cpu`       | `own`（既定）            | `own`                                                      |
   | `clock_set`        | `enabled`                | `enabled`（H-3 の確かめで `unsupported` を見るため。§4.7） |
   | `d_u16_write_mode` | 既定の `disabled` のまま | 同                                                         |

   書込みの許可リスト（`d_u16_write_allowlist`・`label_write_allowlist`）は要らない（`clock_set` はそれらと独立。t12 も `clock_set` だけで通している）。接続の設定は保留キューを通るので、保存して**適用**する。

2. 収集グループ（周期 1000 ms）とタグを作る。

   | タグ                  | アドレス     | 型  | 用途                                                                   |
   | --------------------- | ------------ | --- | ---------------------------------------------------------------------- |
   | `clk_y`〜`clk_w`（7） | D1000〜D1006 | u16 | §1.2 案 A の `DATERD` の時計（本当の値）                               |
   | `sd210`〜`sd216`（7） | SD210〜SD216 | u16 | SD の中身の時系列（Q は SD210〜SD213 の 4 本、BCD を 10 進で読んだ値） |
   | `sm210`〜`sm213`（4） | SM210〜SM213 | bit | 状態の時系列                                                           |

   SD・SM はタグとしては読取り専用で、読めるのは見込み（範囲は Unknown で 1 本ずつ読む）。登録・読取りが通るかは当日確かめる（要確認）。通らなければ GX Works のモニタだけで見る。

3. 収集を始め、接続が「接続済み」になるのを待つ。
4. `GET /api/plc-connections/{id}/clock-sync` で `settings.enabled` が `false` であることを確かめる（以後この値を変えない）。

### 3.6 ゲストの手順（期待の元）

ゲストの実装（banto-driver-wasm `5281578` の `slmp-component/src/clock.rs`・`clock_read.rs`）から言えること。

**時計合わせ（iQ-R だけ）**: 送る前に `clock_set` → 日付 → 機種 → 宛先の順に確かめ、どれかで断るときは何も送らない（`clock_set` が無効・日付の不正は `rejected`、標準 Q・Q25PRH・FX5・型式未知・他局は `unsupported`）。送るのは次の 4 段。

1. SM210–SM211 を 0401 のビットで読む。SM210 が ON なら書かずに `rejected`（"previous clock set request still pending (SM210 ON)"）。**SM211 は見ない**。
2. SD210–SD216 に年・月・日・時・分・秒・曜日（ゲストが計算）を 1401 のワードで書く。
3. SM210 を 1401 のビットで ON にする。
4. SM210–SM211 を読む（最大 3 回）。**SM211 を先に見て** ON なら `device`（code 211、"SM211 clock data set error: the CPU rejected SD210-SD216"）。SM210・SM211 とも OFF なら `ok`。3 回目も SM210 が ON なら `verificationFailed`（"SM210 still ON after 3 reads; unknown whether the clock was set"）。読み直しの間隔は SLMP の往復の時間だけ（待たない）。

どの段でも PLC の終了コードは `device`（code は終了コード、以降は送らない）。(3)・(4) の終了コードでは時計が既に変わっているかもしれない（メッセージにそう書く）。

**読取り（iQ-R・標準 Q・L）**: PLC に何も書かない。`clock_set` は見ない。

1. SM210–SM213 を 0401 のビットで読む。SM213 が OFF なら `rejected`（"SM213 is OFF, so SD210-SD216 do not hold the current clock; …"）。次に SM210 が ON なら `rejected`（"a clock set request is pending (SM210 ON), …"）。SM211・SM212 は見ない。
2. SD210–SD216（iQ-R、BIN）・SD210–SD213（Q、BCD）を 1 回で読む。暦にない日付・範囲外・BCD でない桁は `verificationFailed`。曜日は使わない。

**Hub の 1 回の手動の時計合わせ**（`apps/banto-hub/core/src/clock_sync.rs` の `run_inner`）: 直前の読取り（`before`）→ 時計合わせ（渡す時刻は broker がジョブを始めるときの PC の現地時刻、秒は切り捨て）→ 直後の読取り（`after`）。前後の読取りは使い回さず毎回新しく読み、結果が何でも時計合わせは止めない。SM213 が ON なら 1 回で SLMP の要求は 8 本（読取り 2 + 合わせ 4 + 読取り 2）、OFF なら 6 本（前後の読取りは段 1 で `rejected`）。

操作:

- SM211 が ON のまま残るなら、`result` は `device`（code 211）だが、D1000–D1006 は PC の時刻に戻っている（時計は合ったのに失敗と報告する）。

判定:

判定は 5 の **1 秒後の SM211 の実測値**を必ず使う（ゲストは SM211 が ON なら SM210 の完了を待たずに終えるので、`device` 211 は処理の前のエラーを読んだだけのこともある）。

### 4.6 R6: H-1（iQ-R、CPU が STOP のときにも合わせられるか）

### 4.7 Q1: H3-1・H3-2（Q）

R1・R2 と同じ操作を Q で行う。違うところだけ書く。

- SD210–SD213 は BCD（2 桁ずつ）。モニタは 16 進で見る（SD210 の上位バイト＝年の下 2 桁・下位＝月、SD211 上位＝日・下位＝時、SD212 上位＝分・下位＝秒、SD213 上位＝年の上 2 桁・下位＝曜日）。Hub のタグは 10 進で出るので 16 進に直して読む。
- 秒は SD212 の下位バイト。H3-1・H3-2 の判定は SD212 の下位バイトが進むかで見る。
- `GET .../clock` は Q でも出る（`ok` なら `plcTime` は BCD を読んだ値）。
- GX Works2 のメニューは GX Works3 と違う（要確認）。

記録は R1・R2 の表と同じ形で、Q の分を別に作る。

### 4.8 Q2: H-3（Q、SM210 は自動で OFF に戻るか）

**Hub からは確かめられない**。いまのゲストは標準 Q の時計合わせを送る前に `unsupported` にするので、Hub は Q の SM210 を一度も書かない。GX Works2 のデバイステストで、ゲストが Q で組むはずの手順（PLAN.md「ゲストの手順（Q）」: SD210–SD213 に BCD で書き、SM210 を ON にする）を手で行う。

前提: Q が RUN。SM213 が OFF（書いた SD を読出しで上書きさせないため）。SM210・SM211 が OFF。

操作:

1. Hub で「今すぐ PLC の時計を合わせる」を 1 回（`clock_set` は `enabled`）。`unsupported`（"standard Q clock set is not supported until it is confirmed on a device whether SM210 turns OFF by itself"）で、時計合わせの要求を送らないことを確かめる（前後の読取りは送る）。`clock_set` が `disabled` だと先に `rejected` になる。
2. GX Works2 のデバイステストで、SD210–SD213 に**今の時刻より +5 分**の BCD を 16 進で入れる（例: 2026 年 11 月 7 日 10 時 15 分 0 秒・土曜なら SD210 = H2611、SD211 = H0710、SD212 = H1500、SD213 = H2006。曜日の値の決まりは要確認）。暦にない日付は使わない。
3. デバイステストで SM210 を ON にする（t0）。
4. SM210・SM211 を 10 秒見続ける。D1000–D1006（`DATERD`）で時計が +5 分になったか、その後も秒が進むかを見る。
5. SM210 が ON のままなら、さらに 30 秒、D1000–D1006 の秒が**同じ値に戻され続けていないか**を見る（ON の間スキャンごとに書くなら時計が止まる）。止まっていたら、すぐに SM210 を OFF にする。
6. SM210 が ON のままなら、デバイステストで OFF にする。もう一度 2–4 を行い、2 回目も書かれるか（OFF→ON で毎回書かれるか）を見る。
7. GX Works2 の時計設定（または同じ手順で今の時刻）で時計を戻す。

期待（QCPU 取扱説明書の範囲で言えること）: SM210 を ON にしたスキャンの END の後に時計へ書かれる。自動で OFF に戻るとは書かれていない。

判定:

- 3 の後 SM210 が自分で OFF に戻る → 「自動で OFF に戻る」（Yes）。Q も iQ-R と同じ 4 段の手順でよい見込み（段 4 の確かめ方は Q で別に決める）。
- ON のまま残るが、時計は 1 回だけ書かれて秒が進む → 「戻らない」（No）。ゲストに SM210 を OFF に戻す段を足す（その次の回の段 1 が「前の要求が残っている」で断らないように）。
- ON のまま時計が止まる（毎スキャン書かれる） → 「戻らず、ON の間書き続ける」。OFF に戻す段は書いた直後に要る。
- 6 で 2 回目が書かれるかも書く。

時計を書かない読取りから始め、戻しやすい順に進める。所要時間は推測の目安。

| --- | --------------------------------------- | -------------------------------- | --------------------------------- |

## 6. 後片付け

1. **時計を戻す**: 戻す手段は、検証の対象の時計合わせに頼らない。iQ-R は GX Works3 の時計設定で PC の時刻（NTP で合っている前提）に戻す。Hub の手動の時計合わせで戻す場合は、**先に SM213 を OFF にしてから**行う（R4 で上書きが見つかったときは、SM213 が ON のままでは戻らない）。どちらの場合も、確かめは SM213 に頼らない読み方（§1.2 の D1000–D1006、無ければイベント履歴か時計設定の画面）で行い、PC の時刻と ±2 秒以内であることを見る（SM213 が OFF の間は `GET .../clock` が `rejected` になるので使えない。使うなら確かめる間だけ SM213 を ON にする）。Q は GX Works2 の時計設定で戻す。SM210・SM211 が OFF であることを確かめる（SM211 が残っていれば R5 の 6 のやり方で記録して OFF にする）。
2. **ゲストの `clock_set` を `disabled` に戻し**、保存して適用する。`GET .../clock-sync` で `settings.enabled` が `false` のままであることを確かめる。
3. 試験用の回路（M100→SM213、`DATERD`）を外して、保存しておいたプロジェクトに戻す（オーナー）。止めた SNTP・GOT の時刻同期を戻す。
4. **一時 Hub を正常に止める**（コンソールなら Ctrl+C。強制終了しない）。止まったことを `hub.log` の終了の行で確かめる。
5. **ログの保全**（止めた後、作業用のフォルダを消す前）: `hub.log`、`hub.sqlite3` と、残っていれば同じ名前の `-wal`・`-shm` を一緒に写す（稼働中に本体だけを写すと、WAL に残った最新の監査行が抜ける）。写した先で `sqlite3 <写し>\hub.sqlite3 "SELECT count(*) FROM audit_log WHERE resource = 'plc_connection_clock_sync'"` を流し、今回の時計合わせの回数と合うことを確かめる。REST の応答の写し、GX Works のイベント履歴（書き出せるなら。要確認）と画面の写しも残す。トークン・鍵は含めない。接続は一時の root ごと捨てるので個別に消さなくてよい（既存の Hub で行った場合は接続を消す。`hub_clock_sync` の行は消えずに孤児で残るが、実行はされない）。
6. 置いたプラグインのディレクトリを消す。P-0a で一時鍵を使ったなら、その鍵と一時鍵入りの exe を消す。
7. インストール済みの Hub・シェルを止めたなら、元に戻す。
