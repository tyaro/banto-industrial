## 2. サブスライス分解と受け入れ

各サブスライスを 1 PR 相当の単位にする。受け入れ条件は desktop-plan §9.4 の該当節を正とし、以下は要点。

### T18-2 初回導線と単票登録

- **T18-2a 単票フォーム刷新（TAG-UX-B / TAG-UX-1）**: 入力順「種別→接続/グループ→名前→アドレス→型」、
  基本設定は常時表示・詳細（表示/スケーリング・しきい値・書き込み安全）を `fieldset`/折りたたみ、
  日本語ラベル先出し（「入力下限 (RawLo)」）、書き込み許可の文言と ON 時の安全影響説明、保存前の
  最終外部名/実機・SIM/書き込み許可の固定確認領域。受け入れ: 基本項目だけで通常タグ登録可、詳細を
  閉じても値保持・詳細エラー時は自動展開。
- **T18-2b プロトコル別アドレス補助（TAG-UX-6）**: 選択プロトコルに応じてアドレス例・対応デバイス・
  占有範囲・bit 指定を切替、入力中に共通 preflight。受け入れ: Modbus 選択時に `D100` を推奨例にしない。
- **T18-2c 登録後分岐と親引継ぎ（TAG-UX-2）**: 「登録して次へ」「登録して閉じる」を分け、連続作業で
  親設定＋明示選択した共通値を保持。
- **T18-2d 初回導線チェックリスト（TAG-UX-A）**: PLC 作成→接続テスト→グループ→タグ→SIM 値確認の
  連続導線、工程ごとの CTA、空状態に不足前工程と移動ボタン、ツリー選択の接続/グループを登録へプリセット。
  受け入れ: 空環境からサイドバー探索なしで最初の SIM 値確認まで到達、親 ID 自動設定で `calc`/`mem` 誤選択を防止。
- **T18-2e T13-3 移管（右クリック作成＋常時表示作成）**: ツリー右クリック作成を補助操作、キーボード/タッチで
  使える常時表示の作成操作を主操作にする。`ux-plan.md` の移管記録は #128 で反映済み。

### T18-3 複製・一括・CSV 更新

- **T18-3a タグ複製（TAG-UX-D 前半）**: 「このタグを複製」、型/単位/スケーリング/しきい値を引継ぎ名前と
  アドレスのみ変更。受け入れ: 既存を上書きせず保存前に差分と外部名を確認。
- **T18-3b 一括操作（TAG-UX-D 中）**: 複数選択＋一括有効/無効・グループ移動。**一括削除は参照影響・復旧方法を
  決めるまでバックログ**。受け入れ: 対象件数と差分を事前表示、一部だけ更新しない。
- **T18-3c 連続登録の基数/bit 連番（TAG-UX-D）**: デバイス番号連番とワード内 bit 連番に分け、SLMP の
  X/Y/B/W/SB/SW/DX/DY の基数・繰り上げをプロトコルパーサと共有。**これは operations §15 の既知未対応
  （16進デバイス・bit 指定が v1 非対応）を解消する項目**。受け入れ: `X1E→X1F→X20`、`D100.14→D100.15→D101.0`。
- **T18-3d CSV 新規/更新分離＋テンプレート（TAG-UX-F）**: 「CSV ファイルを選択」表示＋テンプレート DL、
  `新規追加`/`既存更新` を別モード、更新は差分プレビュー（追加/変更/変更なし/エラー）後にだけ適用・暗黙削除なし、
  サイズ/行数上限・文字コード・チャンク/Worker・仮想化、出力範囲（全件/絞り込み/選択行）。受け入れ: Excel 上の
  実行番号とエラー行一致・エラー CSV 再 DL、上限超過は解析前に理由付き拒否。
- **T18-3e BantoGrid セル編集/TSV 貼付の接続（TAG-UX-D 後半）**: 全構成 preflight・差分確認・all-or-nothing API・
  停止中ロックを整備してから接続。**依存が重いので T18-3 の最後、または独立スライス候補**（§4-2 参照）。

### T18-4 モニタと確認導線（T13-2 移管）

- **T18-4a モニタの Tree/検索統合（T13-2）** ✅完了: monitor ページのドロップダウンフィルタを登録と同じ Tree＋検索へ置換。
  絞り込みは純関数 `filterMonitorRows`（`apps/banto-hub/src/lib/banto/monitorFilter.ts`）に切り出し、WS 購読ロジックは無改修
  （購読最適化は T18-4b）。
- **T18-4b 選択購読と再接続堅牢化（TAG-UX-H の一部）** ✅完了: 選択グループだけを WS 購読（全タグ更新ごとの全行走査回避）、
  WS バックプレッシャ `1013` 切断の状態表示、自動再接続・再購読・初期スナップショット受信まで旧値を現在値扱いしない。
- **T18-4c 確認導線** ✅完了: タグ登録画面の新規/複製/編集/連続登録/CSV新規取込/CSV更新取込/一括操作の
  各成功後に「確認」バナーを出し、モニタの対象グループ（単一グループに確定できる場合）・対象タグ
  （`focus`、新規/編集は常時・それ以外は省略）へディープリンクする。リンク先の組み立ては純関数
  `monitorHref`（`apps/banto-hub/src/lib/banto/tagOnboarding.ts`）が担い、モニタ側は `?group=`/
  `?connection=`/`?focus=` を初回マウント時のみツリー選択・持続的な行ハイライト（`.confirm-target`、
  一時的な `.flash` とは別物）へ反映する。収集稼働中の 202 キュー投入（`QueuedWhileRunningError`）時は
  既存の try/catch 構造上バナーの代入行に到達しないため、追加分岐なしで自然に CTA を出さない。

## 3. 推奨実行順

依存とテスト PLC/実機の要否から:

1. **T18-2**（a→b→c→d→e）— 単票登録の基盤。以降の複製/一括/モニタが乗る土台。
2. **T18-3**（a→b→c→d、e は最後/別スライス）— 日常大量編集。T18-3c は既知未対応の解消を含む。
3. **T18-4**（a→b→c）— モニタ統合。T18-2 の Tree/検索を再利用。
4. **T18-5**（a→b→c→d）— 性能・検証。a/b は自走可、c/d は**オーナーの Windows 実機＋テスト PLC が必要**（Phase 2/soak と同席で）。

横断 TAG-UX-E は T18-3/T18-4 と同時、TAG-UX-G は各スライスの受け入れに織り込むのを既定案とする（§4-1）。
自走可能なフロント実装（T18-2/T18-3/T18-4a-c/T18-5a-b）は sonnet サブエージェント→上位レビュー→PR で進め、
実機検証（T18-5c/d）はオーナー同席の対話セッションで行う。

## 4. 決定事項（2026-08-12 オーナー決定）

1. **TAG-UX-E / TAG-UX-G の扱い** → **既定案採用**: E（検索/一覧）は T18-3/T18-4 に統合、
   G（アクセシビリティ/狭幅）は各機能スライスの受け入れ条件へ織り込む。
2. **BantoGrid セル編集/TSV（T18-3e）** → **既定案採用**: 独立スライスへ切り出す
   （全構成 preflight・all-or-nothing・停止中ロックを整備してから接続）。
3. **性能閾値の対象 PC 基準** → **Intel Core i5 第11世代・メモリ 8〜16GB** を基準マシンとする。
   「10,000 タグ・500 グループで初期操作可能まで 2 秒 / 検索 p95 100ms / 1,000 件 dry-run・適用 5 秒」を
   この基準機で満たすことを T18-5a の性能目標とする。
4. **一括削除** → **バックログ据え置き（承認）**。実装する場合の代案は以下（着手判断は将来）:
   - **代案 B（可逆な既定・推奨）**: 一括「無効化」（T18-3b）を「収集から外す」主操作として前面に出す。
     無効化は収集停止のみで破壊せず**可逆**なので、多くの用途は削除不要で済む。
   - **代案 A（真の削除が要る場合）**: 単票削除（TAG-UX-C）が持つ「演算タグ等の参照影響＋完全外部名の表示」を
     一括へ拡張。選択セット全体の参照影響を集約表示し、参照タグがあれば警告/ブロック、明示確認を必須にして削除。
     復旧は undo ではなく「削除前の差分プレビュー＋事前 CSV エクスポートでのバックアップ」で代替。
5. **着手範囲** → **T18-2 全体を 1 群として着手可**。実装は a→b→c→d→e のサブ PR で刻んでレビュー可能に保つ。
