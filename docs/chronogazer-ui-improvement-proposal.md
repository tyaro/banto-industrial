## 1. 目的

ChronoGazer を PC 上のペーパーレス記録計として使いやすくする。監視では横河電機やキーエンスの記録計で馴染みのある、時間軸を持つトレンド、現在値、警報・イベントの確認を中心に据える。設定では HUB と共通した「左で対象を選び、その場で設定する」操作にする。特定製品の画面をそのまま複製する意図はない。

優先順位は、学習の容易さ、設定の簡易さ、日常操作の速さ、視認性とする。監視・履歴・設定で表示グループ名、ペン名、色、単位を揃える。左ツリーと画面見出しで分かる階層を、パンくずや説明文で繰り返さない。ChronoGazer は読み取り・記録・表示を担い、PLC への書き込み操作は設けない。HUB のタグモニタでの手動書き込みは[HUB 画面改善案](banto-hub-ui-improvement-proposal.md)で扱う。

## 2. 用語と画面の分担

| 用語           | 意味                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| 接続先         | HUB、または PLC 直結（SLMP・Modbus）。タグの値を受ける相手                     |
| 収集グループ   | 接続先の下にある収集周期などの単位。表示グループとは別                         |
| 記録項目       | ChronoGazer に登録したタグ。記録する対象                                       |
| 表示グループ   | 監視・履歴で切り替える画面の単位。複数のペンと表示形式を持つ                   |
| ペン           | 表示グループ内で記録項目を参照する表示系列。記録項目そのものの複製ではない     |
| 表示パネル     | 一つのトレンド、数値一覧、棒メーターなど。混在表示では複数パネルを並べる       |
| 時間帯別積算値 | 指定した時間帯の使用量・流量など。累積計の差分または瞬時値の時間積分から求める |

監視画面の上部には表示グループのタブを置く。監視中は左ツリーを収納し、チャートと数値に画面幅を使う。タブが多い場合は横スクロールまたは一覧から選べるようにする。設定画面の左ペインには表示グループをツリー形式の一覧で並べ、選んだグループの編集内容を中央に表示する。現行上限の 16 グループに不要な階層を作らない。監視と設定の選択対象は同じ表示グループを指す。左・右ペインは幅を調節・収納でき、狭い画面では中央を優先する。

### 2.1 banto 系の共通の型への当てはめ（2026-11-17 オーナー決定）

HUB と同じ型（メニューバー＝機能、左ツリー＝対象、中央＝「一覧」と「設定」のタブ、右ペイン＝行の詳細。[HUB 画面改善案](banto-hub-ui-improvement-proposal.md) §共通の画面構成）にする。用語は HUB と同じ「接続先」「収集グループ」に揃える。

メニューバーの並び: **監視 / ヒストリカル / イベント / 記録 / 表示グループ / 管理 ▾ / 設定**。既定はメニューバーにする（監視は「メニューバー＋表示グループのタブ」の 2 段になり、チャートの幅を最大に取れる）。

| ページ       | 左ツリー                                          | 中央のタブ                                                        | 右ペイン                           |
| ------------ | ------------------------------------------------- | ----------------------------------------------------------------- | ---------------------------------- |
| 記録         | 接続先 → 収集グループ（HUB のタグページと同じ木） | 記録項目の一覧 / 接続先・収集グループの設定（周期など）           | 記録項目の詳細                     |
| 表示グループ | 表示グループの一覧（1 階層）                      | ペンの一覧とプレビュー / グループの設定（表示形式・テンプレート） | ペンの設定、またはタグの選択（§4） |

今の「タグ設定」「グループ設定」は、それぞれ「記録」「表示グループ」になる。二つを一つのページにまとめる案は、HUB と型を揃えるため採らない。 呼び名は 2026-11-18 に画面へ反映済み（#1179 PR4a）。

2026-11-18（#1179 PR4b）: 「記録」ページをこの型にした。実装での判断:

- 左ツリーは「すべて / 接続先 / 収集グループ」（記録項目は出さない）。接続先は行頭のアイコンで Hub 経由か PLC 直結かを分け、「無効」「シミュレーション」の印を付ける。上のツールバーに「接続先を追加」（PLC 直結。Hub 経由は今どおり「Hub から追加」が作る）と「収集グループを追加」。
- 中央の「設定」タブは、接続先か収集グループを選んでいて編集者以上のときだけ出す。旧い「接続」「収集グループ」の一覧グリッドは無くし、その列にしか無かった情報（「動作」＝シミュレーション、ドライバ設定）は、ツリーの印と「設定」タブのフォームで分かるようにした。
- 右ペインには、記録項目の詳細（編集・しきい値・削除）のほか、作成フォーム（記録項目・接続先・収集グループ）も出す。中央の一覧を見ながら作れるようにするため（HUB の右ペインの新規作成と同じ）。作成に成功したら閉じ、接続先・グループは作ったものをツリーで選ぶ。
- 記録項目の追加は収集グループを選んでいるときだけ（HUB の 2026-11-18 オーナー決定と同じ）。
- 選んだ対象とタブは URL に持つ（`?target=connection:<id>|group:<id>&tab=settings`、既定は書かない）。対象・タブを変えると右ペインは閉じ、未保存のフォームがあれば確かめる（キャンセルなら元のまま）。
- 削除に伴う移動（接続先・収集グループを消した後）は例外で、右ペインを閉じない。無関係な作成フォームの下書きを確認なしに捨てないため。作成フォームの親の選択欄（収集グループの追加の「接続」、記録項目の追加の「収集グループ」）が消したものを指していたら、その欄だけ未選択に戻す。

## 3. 監視・履歴画面

### 3.1 基本表示

- 上部: 表示グループのタブ、収集中・記録中の状態、現在時刻。受信できていることとファイルへ記録できていることを別に示す。
- 中央: 選んだ表示グループのトレンドまたは定型パネル。時間軸、目盛、線の色・種類、単位、欠測区間、しきい値、イベント位置を読めるようにする。
- 補助: ペンの現在値と品質。ペンを選ぶと線と現在値を強調し、個別の表示・非表示を切り替えられる。全画面表示では設定用の部品を隠す。
- 履歴: 監視中と同じ表示グループ・ペンを初期選択とし、期間指定、ズーム、パン、CSV 出力へ進める。履歴は現行計画では R2 の機能であり、完成済みとして扱わない。

現行のトレンドは、しきい値の帯を選んだ 1 ペンにだけ描く。時間窓は端末ごとに保存し、表示グループの定義には含めない（[記録計要件](recorder-requirements.md)）。複数ペンのしきい値を同時に描く、または時間窓をグループの既定として保存する場合は、現行仕様の変更として扱う。

ライブ追従を一時停止して時刻を調べる場合も、収集・記録は止めない。「ライブ」「表示停止中」「履歴」を区別し、「最新へ戻る」で追従を再開する。同じ時刻を示す共通カーソルで全ペンの値と品質を読めるようにする。表示上の一時的な非表示と、グループ設定として保存する既定の表示は区別する。

前日・前勤務帯との比較、イベント発生時刻への移動、カーソルで選んだ区間の差分は、履歴画面が成立した後の追加候補とする。

値が無い場合は 0 と区別する。bit は既定の `True` / `False` 表示を維持する。異なる単位の系列を共通の数値軸へそのまま重ねると読み違えるため、単位・尺度ごとにパネルを分けるか、ペンごとの表示レンジを明示した百分率表示を選べるようにする。

### 3.2 表示形式

現行の表示グループは、トレンド・デジタル・バー・計器の 4 種から一つを選ぶ（`apps/chronogazer/core/src/display_groups.rs`）。本案ではこの 4 種を土台とし、名称を「トレンド」「デジタル現在値」「棒メーター」「円形計器」として利用者に示す。混在表示は、利用頻度が高い「トレンド＋現在値」を先行し、「トレンド＋棒メーター」「同じ時間軸のトレンド 2 段」など数を絞ったテンプレートを追加する。既定では同じペン集合・順序・色・レンジをパネル間で共有し、必要なときだけ個別指定する。テンプレートを切り替えても既存のペン設定を失わせない。自由な座標配置や汎用画面エディタにはしない。

**棒メーター**は現在値を示し、**時間帯別積算の棒グラフ**は期間ごとの量を比較する別の表示形式とする。名称と操作を混同しない。円グラフは、同じ期間・同じ単位で合計に対する内訳を示せる場合に限る。時系列の値を円グラフへ無条件に割り当てない。

### 3.3 トレンドの統計表示

通常の値の線に加え、必要なペンにだけ次の表示を重ねられるようにする。初期表示は元の値を優先し、計算による線や帯には計算条件と「統計表示」の区別を付ける。bit や文字列など、意味のない型には選択肢を出さない。

| 表示               | 操作と意味                                                                                             | データ上の条件                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 移動平均           | 選択ペンに時間窓を指定し、元の線と平均線を重ねる。窓の長さと使用できたデータの割合を示す               | 品質の悪い値と欠測を平均へ混ぜず、十分な値が無い区間をつないで見せない       |
| σ・標準偏差        | 選択期間または移動窓の平均と ±1σ・±2σ・±3σ の帯を選んで表示する。基準期間と件数を示す                  | しきい値・警報とは別物として扱い、正規分布や異常判定を暗黙に仮定しない       |
| ローソク足         | 指定した時間幅ごとに始値・高値・安値・終値を表示する。まず選択した数値ペンを単独で確認できるようにする | 区間内の時刻順の元サンプルから四値を求め、欠測区間を通常の足として描かない   |
| 広い期間の MIN/MAX | 表示幅に対してサンプルが多いとき、区間の最小値・最大値を帯または縦線で描き、短い山や谷を残す           | 最小値と最大値の中点だけで代表させず、拡大時の元サンプルと表示の意味を揃える |

現行の履歴 API は区間の最小・最大を返すが、リアルタイムトレンドの初期窓は中点を 1 本の線として描く（`apps/chronogazer/src/lib/monitor/trendLogic.ts`）。広い期間の MIN/MAX 表示には既存の包絡を描画まで通す変更が要る。ローソク足の始値・終値、移動平均、σ はこの最小・最大だけから正しく復元できないため、保存済みの元データを対象にした集計 API が必要である。グラフ用に間引いた点を統計や積算の計算元にしない。16〜32 ペンで一斉に全統計を描くのは既定にせず、選択ペンから使えるようにする。

### 3.4 ペン数と視認性

現行は 1 表示グループ最大 8 ペン、表示グループ最大 16 個である。本案では**1 グループに最大 32 ペンを登録し、トレンド 1 面には最大 16 ペンを表示する**ことを暫定目標とする。17〜32 ペンを同時に見る場合は、時間軸を同期した 2 段のチャートに分ける。表示を絞っても記録項目の保存は止めない。

16 本以上では色だけで線を識別しにくい。ペン名で探せる凡例、選択した線の強調、個別の表示・非表示、線種の違いを併用する。通常は 4〜8 本を読みやすい初期表示とし、必要なら 16 本を同時に選べる。2 段表示では時間軸とカーソルを同期し、同時刻の値を一覧で読む。単位や設備ごとに振り分けられるようにし、「選択のみ表示」「全て戻す」を用意する。数値・メーターのパネルでは、全ペンを一度に大きく見せるのではなく、一覧性と現在値の読みやすさに合わせて配置する。

この上限は**表示の上限**であり、ChronoGazer 全体で記録できるタグ数の上限ではない。現行は表示定義・色が 8 枠で、履歴 API も 1 要求 8 タグ、合計 8,000 区間点までである。いまの合計上限のまま本数を増やすと、1 本あたりの区間は 8 ペンの 1,000 から、16 ペンで 500、32 ペンで 250 に減り、広い期間の山・谷が読みにくくなる。16〜32 ペン化には定義の検証、色と線種、凡例、履歴取得の分割または API の見直し、描画性能の計測が必要で、定数だけの変更では成立しない。最終上限は 16 本・32 本の画面評価と性能試験後に決める。

### 3.5 積算・内訳・メモ

時間帯別積算グラフは、1 時間、勤務帯、1 日などの区切りを選べるようにする。利用者は「積算メーター」または「瞬時流量・電力」など用途から選び、計算方法と入力・出力単位をプレビューで確かめる。累積計なら期間の差分、瞬時値なら時間積分として計算する。日の開始時刻、勤務帯、欠測、品質不良、計器のリセット・桁あふれ、部分的な時間帯の扱いを定義してから数値を表示する。不完全な区間は有効データ率とともに区別し、推定値を正常値のように見せない。グラフ用に間引いた履歴を積分の計算元にしない。

円グラフは同じ期間・単位に加えて、内訳が重複しないこと、負値を含まないこと、合計と未割当分の意味が明確であることを条件にする。ゼロ合計・欠測時は割合を出さない。初期は量の比較に向く棒グラフを優先し、円グラフは割合確認の後続表示とする。

チャートのメモは画面上の座標ではなく時刻に紐付ける。追加を始めた時点で時刻を固定し、保存前に対象と時刻を確認できるようにする。「この表示グループのメモ」と「設備・タグのメモ」を区別し、別の表示グループから同じタグを見た場合とグループ削除後の扱いを決める。記録中のチャートから追加し、履歴でも同じ時刻から開けるようにする。メモには本文、作成者、作成・更新時刻を保存し、値や警報の原記録は書き換えない。閲覧・編集権限と監査、CSV 等への出力範囲は実装前に決める。検索、定型文、期間メモは後続候補とする。

## 4. 表示グループの設定とタグ追加

「表示グループ」ページは `左: 表示グループ一覧 | 中央: タブ「ペン」（プレビュー・ペン一覧）と「設定」 | 右: 選択したペンの設定` とする（§2.1）。左はツリーに見える形式でも、最初は表示グループだけの一階層とし、不要な親子関係を作らない。タグ数が多くてもタグを常時展開しない。グループの作成、複製、名前変更、並べ替え、削除を左側で行い、中央でテンプレートとペン配置を確認する。選択したペンの色・線種・表示レンジは右側で編集する。幅の狭い画面や表示倍率 125% でも中央の設定内容を読めることを確認する。

「タグを追加」を押すと、右ペインをタグ選択に切り替える。「タグ追加中・追加先: ○○」と戻る操作を固定表示し、元の選択ペンを保持する。タグ選択では `接続先 → 収集グループ → タグ` をたどり、検索もできる。検索結果には名前だけでなく接続先、収集グループ、単位、現在値、品質を併記し、似た名前のタグを取り違えにくくする。タグをダブルクリックすると、現在選んでいる表示グループの**未保存の編集内容**へ追加する。初めての利用者にも操作が見つかるよう、タグ行の「追加」ボタン、複数選択したタグをまとめて追加する操作、キーボード操作も置く。追加、順番変更、ペンの削除は保存前に取り消せる。登録済みや上限超過はその場で示す。大量のタグは遅延読込と検索で扱い、数万件を一度にツリーへ描かない。

HUB のカタログにあるが ChronoGazer に未登録のタグを選んだ場合も、ダブルクリック時点では下書きに留める。「保存」で記録項目の登録とペンへの割り当てをまとめて確定し、一方だけ残さない。実現には現在別々の登録・表示グループ更新を一つの保存単位にする新しいサーバー処理が必要である。初回の収集グループ・周期は既定値を提示し、必要なときだけ変更できるようにする。数値と bit 以外など、現在取り込めないタグは理由を表示する。記録項目として登録済みのタグはペンへの参照だけを追加し、二重登録しない。実データが未受信の場合のプレビューは見本と明示する。

2026-11-18（#1179 PR5）: この保存単位をサーバーに作った。新しい口は足さず、**表示グループの作成・更新（REST `POST /api/display-groups`・`PUT /api/display-groups/{id}`、MCP `create_display_group`・`update_display_group`、Tauri の同名のコマンド）をそのまま一括保存にした**。表示グループを保存する口は一つだけになる。

- ペンは `tagId`（登録済みの記録項目）か `hubTag`（Hub のカタログの行: `externalName`・`name`・`dataType`・`unit`・`decimals`）のどちらか一つで指す。今までの `{tagId, colorSlot}` の本文はそのまま通る。
- `hubTag` の外部名が登録済み（Hub 接続の下のどれかの記録項目）なら、その記録項目を参照するだけで二重に登録しない。未登録なら、本文の `hubTagGroup`（既存の Hub 接続の収集グループ `collectionGroupId` か、新しく作る `newGroup`）へ登録する。登録の規則（数値と bit だけ、名前の衝突は行の誤り、Hub 接続の暗黙の作成）は「Hub から追加」（`POST /api/tags/from-hub`）と同じ処理を使う。未登録のものが無ければ `hubTagGroup` は使わない。
- 登録と表示グループの書き込みは一つのトランザクションで、どちらかで落ちれば何も残らない。誤りは `pens[i].hubTag.*`・`hubTagGroup.*` の位置で返す。
- 応答は表示グループに加えて、今回登録した記録項目（`registeredTags`、無ければ出さない）。MCP は登録があったときだけ `restartRequired: true` を付ける。登録があれば、記録項目の作成の監査と Hub の購読への反映も行う。
- `config` スコープの API キーもこの口を通るので、キーでも Hub のタグを登録できる。汎用の `POST /api/tags` で Hub 接続のグループに記録項目を作れるのと同じ扱いで、`/api/tags/from-hub` をキーで通さない今の決まり（[AI エージェント向け API](chronogazer-agent-api-design.md) §3.3）は変えない。

2026-11-18（#1179 PR6a）: 「表示グループ」ページを §2.1 の型（左: 一覧、中央: 「ペン」「設定」タブ、右: ペンの設定）にした。実装での判断:

- 下書きはグループ単位で一つのまま。保存・取り消し・未保存の表示・楽観ロックの「最新の内容を読み込む」は中央の上（どちらのタブでも見える所）に置く。ペンの編集（右ペイン）も「設定」タブも同じ下書きを書き換えるので、タブの切り替えやペンの選択・右ペインを閉じる操作では未保存の確認を出さず、**別のグループへ移るとき（新規作成へ移るときも）だけ**確かめる。
- 選んだグループとタブは URL に持つ（`?group=<id>&tab=settings`、既定は書かない。新規作成中は `?group=new&tab=settings` で、下書きは URL に持たない）。グループ・タブを変えると右ペインは閉じる。作成に成功したときだけ、右ペインを閉じずに URL を作ったグループへ置き換える。
- 右ペインは編集者以上が「ペン」タブでペンの行を選んだときだけ開く。ペンを追加するとそのペンの設定が右に開く。タグの選択は今までの登録済みの記録項目の `<select>` をそのまま移した（Hub のカタログからの選択と `hubTag` での保存は PR6b）。しきい値は中央の行に読み取り専用で出し、右ペインには出さない。
- 閲覧者は一覧と各グループの中身（ペンの行・「設定」の入力欄）を見られるが、入力欄は無効で、右ペインは開かない。
- 左の一覧は `BantoTree` でなく従来の行ボタンのまま（1 階層で、並べ替えの ↑↓ を行に持つため）。

操作の状態は「編集中 → 保存済み・未反映 → 記録中」として示す。保存後に収集への反映や再起動が必要なら、その影響を示して「記録へ反映」を一か所から実行できるようにする。表示グループからペンを外しても記録項目そのものは削除・停止しない。未保存のまま別のグループへ移動する場合は入力を失わせない。グループの複製、複数ペンの表示属性の一括変更、編集の取り消しを用意し、16〜32 本の反復設定を減らす。

## 5. HUB への接続

### 5.1 利用者の操作

接続先の選択肢は**「ChronoGazer が動く PC の HUB」と「別 PC の HUB」**の二つにする。前者には PC 名を表示する。LAN ブラウザで設定画面を開いても、ブラウザ端末の PC を指すように見せない。現行の ChronoGazer は HUB 接続を 1 つまでしか持てない（[タグサーバー設計](tag-server-design.md) §7）。二つの選択肢は同時に使うものではなく、どちらか一方への切り替えである。

| 接続先         | 初回の操作                                                                                     | 次回以降                       |
| -------------- | ---------------------------------------------------------------------------------------------- | ------------------------------ |
| 同じ PC の HUB | 起動中のローカル HUB を確認し、準備済みなら自動接続。URL、IP、ポート、API キーの入力を求めない | 保存済みの連携を使い自動再接続 |
| 別 PC の HUB   | IP アドレスを入力して接続。標準ポートを既定にし、変更時だけ詳細設定を開く                      | 保存済みの接続先へ自動再接続   |

LAN の自動探索は行わない。LAN の初回は `IP 入力 → HUB 名と接続先の確認 → 初回認証 → タグ選択` とし、IP の入力だけで認証まで完了するようには見せない。接続後は HUB 名、接続状態、受信状態、利用できるタグ数を示し、そのままタグ選択へ進める。HUB が停止中、未導入、認証待ち、通信不能、タグが無い場合はそれぞれ次の操作を表示する。ローカルの承認待ちは承認先を開く導線を示し、完了を検知したら自動で続行する。接続済みという表示だけで、値の受信やファイルへの記録まで成功したと判断させない。

### 5.2 現行方式との差分と認証

現行の ChronoGazer は接続先 URL を入力する。同一 PC の試運転中の HUB には読み取り用 API キーを自己発行できるが、ロックダウン済みの HUB は手動発行したキーの採用が必要である。同一 PC の接続は HUB サービスの証明書を pin した `https://127.0.0.1:8723` に限り、サービス版 HUB と証明書の準備を前提とする。LAN の HTTP は現行では許される一方、LAN の HTTPS/pin は未整備である。

同じ PC の HUB の自動接続では、既存の証明書確認と保存済み資格情報を再利用する。試運転中は既存の読み取りキー自己発行を使える。**ロックダウン済みで未連携の場合に、認証を迂回して無条件にキーを発行することはしない。**初回だけ HUB 管理画面で「この PC の ChronoGazer に読み取りを許可」する操作、または導入時の安全なローカル資格情報の受け渡しを新設する。HUB 側の承認後は API キーのコピー入力を不要にする。サービス証明書の準備も導入手順に組み込み、利用者に URL や証明書のパスを入力させない。

別 PC の HUB は IP 指定とする。標準ポート以外、名前解決や特殊なネットワーク構成は詳細設定で扱う。HUB はロックダウン前に loopback 以外で待ち受けることを拒否する（[HUB クライアント接続](banto-hub-client-bootstrap.md) §7）。したがって**別 PC から見える HUB は必ずロックダウン済み**であり、読み取りキーの自己発行は使えない。初回認証は現行の手動キー採用か、新設する HUB 側の承認手順のどちらかになる。キー入力まで無くすには HUB 側の承認手順と LAN の安全な通信方式を別途設計する必要がある。LAN 上の未知の HUB に自動で資格情報を送らない。接続先を変更するときは既存の連携を黙って別の IP へ持ち越さない。

現行の LAN 接続は pin の無い HTTP で、API キーは平文で LAN を流れる。「IP を入れるだけ」の操作を標準にすると、この平文の経路を使いやすくすることになる。LAN の IP 入力を標準の操作にするのは、LAN の HTTPS と証明書の確認方式を決めてからとする。それまでは平文であることを接続画面で示す。

## 7. 確認項目と未決事項

設計の確認では、PC に詳しくない利用者が、説明なしで次を行えるか試す。

1. ChronoGazer が動く PC の HUB に接続し、URL・API キー・ポートの入力なしでタグを選ぶ。LAN の場合は IP を入力し、初回認証と接続先の確認を経て進む。
2. 似た名前のタグから 16 本を選び、誤追加を取り消し、保存して記録へ反映する。値が出ないとき、未保存・未反映・受信異常を見分ける。
3. 別の表示グループへ移って戻り、表示順と設定が保たれる。欠測とゼロ、受信中と記録中、ライブ停止中と記録停止中を見分ける。
4. 選択ペンを強調して同時刻の値を読み、広い期間でも短い山・谷を MIN/MAX 表示で確認する。移動平均・σ・ローソク足の計算条件を見つけられる。

所要時間、タグの取り違え、援助回数、状態の誤判断を記録する。1366×768・表示倍率 125% とフル HD で中央の設定・凡例を確認する。32 ペンは同期 2 段表示の視認性、履歴取得時間、表示の応答を測ってから上限を確定する。

実装前に決める項目は、タグ登録と表示割当の一括保存・記録への反映、ロックダウン後のローカル初回承認方式、LAN の HTTPS と証明書の確認方式、LAN のキー不要連携を採用するか、複数ペンのしきい値表示と時間窓の保存先、混在テンプレートの種類、16/32 ペンの最終上限と履歴 API の区間数、移動平均と σ で時間加重するか（サンプル間隔が不揃いな場合）と欠測条件、σ の基準期間・母集団と標本の扱い、ローソク足の時間幅と欠測条件、時間帯別積算の計算規則、メモの権限・監査・出力範囲である。これらは本書の提案だけで現行の確定要件を上書きしない。

## 8. AI エージェントからの設定（2026-11-17 オーナー決定）

ChronoGazer も、HUB と同じく AI エージェントから設定できるようにする。今の ChronoGazer の REST は管理 UI のログインのセッションを前提とし、API キー・MCP・OpenAPI を持たない。

- **API キー**: ログインできないエージェントのため、スコープ（読み取り / 設定の変更）を持つ API キーを足す。操作は監査ログにキーの ID で残す。
- **MCP**: HUB の MCP（`apps/banto-hub/core/src/mcp.rs`、自前の JSON-RPC、`POST /mcp`）の骨組み（受け付け・ツールの登録・エラーの形）を本リポジトリの共有 crate に切り出し、ChronoGazer はツールを足すだけにする。
- **処理は一つ**: ツールは REST と同じ処理を呼ぶ。§4 で新しく作る「記録項目の登録とペンの割り当ての一括保存」も、UI・REST・MCP で同じ処理を使う。
- **OpenAPI**: HUB と同じく REST に付ける（エージェントが REST を直接使う場合のため）。

ChronoGazer は PLC への書き込みを持たないので、エージェントが変えられるのは ChronoGazer 自身の設定（接続先・記録項目・表示グループなど）に限る。

設計は [ChronoGazer の AI エージェント向け API](chronogazer-agent-api-design.md)（#1161、2026-11-17）。REST は今の `/api/*` でキーを受け、スコープは `read` と `config`、MCP からのキーの発行は許さない。
